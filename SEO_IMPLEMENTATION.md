# SEO Implementation (STEP 35)

What is implemented, where it lives, and what it does **not** claim. No search ranking, traffic or performance result is claimed here: those can only be measured after release (see "Measured results").

## Metadata

- Every public page gets its title, description, canonical URL, Open Graph and Twitter card from one registry, `src/lib/public-site/routes.ts`, through `pageMetadata(path)` (`src/lib/public-site/seo.ts`). A page that is not in the registry fails to build its metadata, so a page cannot ship without an entry.
- Titles are unique and at most 70 characters; descriptions are 60–170 characters (checked by tests). The spec's example titles are used for Home, How It Works, Verification, For Families and Pricing.
- The root layout sets `metadataBase` (from `APP_URL` / `NEXT_PUBLIC_APP_URL` / `NEXTAUTH_URL` / the Vercel production URL), the viewport and theme colours.
- Content pages (blog, guides) use `contentMetadata()` with the item's own search title and description (falls back to its title and summary), `og:type=article`, published and modified times.
- A default social image (`src/app/opengraph-image.png`, the brand mark on the brand background, no text or claims) and an Apple touch icon are generated by `scripts/generate-pwa-assets.mjs`.

## Indexing rules

- **Indexed:** pages marked `indexable` in the registry, blog and guide items that are live and not marked `noindex`, and published landing pages an editor opted in.
- **Not indexed, two independent layers:**
  1. `robots.txt` (`src/app/robots.ts`) disallows `/admin`, `/api/`, `/dashboard`, `/family`, `/my-`, `/account-settings`, `/maintenance`, `/private`, `/internal`.
  2. `X-Robots-Tag: noindex, nofollow, noarchive` on the same areas (`next.config.ts`, list `PRIVATE_NOINDEX_PATHS`). A test compares the list with the account page folders so a new `my-*` page cannot be forgotten.
- **Utility pages** (`/login`, `/forgot-password`, `/report-concern`, `/update-request`, `/register/confirmation`, `/offline`) are crawlable but carry `noindex` in their own metadata, so the tag can be read.
- Filtered or paged blog/guide lists (`?category=`, `?tag=`, `?page=`) are `noindex,follow` and canonicalise to the list page.
- There is no public applicant directory, no public search and no page that lists profiles; a test asserts it.

## Sitemap

`/sitemap.xml` lists every indexable registry page, live blog articles and guides (not `noindex`), and published landing pages that were opted in. No last-modified date is invented for fixed pages. It is empty when no canonical base URL is configured (the site then has nothing absolute to publish).

## Structured data (JSON-LD)

Built in `src/lib/public-site/structured-data.ts` and rendered by `JsonLd`, which escapes `<` and the Unicode line separators so no text can close the script tag.

| Type | Where |
|---|---|
| Organization, WebSite | Home |
| WebPage, BreadcrumbList | Every page built with `PageShell` |
| FAQPage | `/faq` and Home — generated from the very list that is rendered, so the markup always matches the visible text |
| Article | Blog and guide items |

Not used, on purpose: ratings, reviews, aggregate ratings, `contactPoint`, `sameAs`, internal-search `potentialAction`. A test fails if any of them appear.

## Content strategy

- Blog and guides are informational and written by named authors; publishing runs a content-policy check (no guaranteed-outcome claims, no "100%", no invented statistics, no privacy or verification over-claims, no links to other sites).
- No articles are seeded: empty lists say "No articles published yet". The topics in the brief (profile creation, compatibility questions, family participation, safe practices, how verification works, preparing for a family meeting) are for staff to write and approve in **Admin → Blog & Guides**.

## Internal linking

Header and footer link every main page; the home page links to How It Works, Verification, Safety, For Families, Pricing and FAQ; each content page links to Register and its list; FAQ answers link to Support and Contact; breadcrumbs on every page. A test checks that every link in the navigation and footer points to an existing page.

## Measured results

Measured on the live site on 2026-10-13 and recorded in `STEP_35_REPORT.md` (device, network and method included): home page FCP and LCP 848 ms on a phone-sized viewport with CLS 0; compressed HTML 6-14 KB per page; 17 URLs in the sitemap; private areas answer `X-Robots-Tag: noindex`. Search ranking and traffic are not measured and not claimed. INP was not measured.

## Owner actions that affect SEO

1. A real public address: set `APP_URL` (until then the `*.vercel.app` address is used and has little search value).
2. Submit `/sitemap.xml` in Google Search Console / Bing Webmaster Tools (needs the owner's account).
3. Have the privacy policy and terms reviewed, then set `LEGAL_PAGES_REVIEWED=true`.
4. Write and approve the first articles and guides.
